# GenericParser 1.6.0

Release date: 2026-08-10

Build: `gp-160-20260810-1`

Preferred API contract: `generic-parser-module-v2`

Compatible API contract: `generic-parser-module-v1`

Worker plan: Cloudflare Workers Paid

Status: Release candidate; production acceptance pending

## Goal

Make GenericParser easier to use directly in the browser and introduce a
clean, reusable module-v2 packet contract without coupling the parser to a
specific catalog or collection project.

## Web interface

- A single prominent search row combines the query, source selection and
  primary action.
- Required, excluded, model-variant and brand terms use removable chips;
  comma, Enter and multi-term paste are supported.
- Search criteria, technical options and result filters are visually and
  semantically separated.
- Recent searches, clearer saved-profile actions and a compact profile preview
  reduce repeated entry work.
- Per-source progress distinguishes active, successful, empty, restricted and
  disabled sources.
- Active result filters are removable chips. Known-total and favorite filters,
  favorite-first sorting and a mobile filter disclosure are included.
- Cards use the user-facing states `Passend`, `Prüfen` and `Unpassend`, retain
  source/product evidence and open the reason primarily for review cases.

## Module API v2

- New project-independent capabilities, validation, single-search and batch
  endpoints under `/api/module/v2/`.
- Up to 100 search definitions per batch; one source page per request.
- Opaque signed continuation tokens with two-hour lifetime and strict binding
  to the unchanged batch definition.
- Stable `source:source_id` listing keys, explicit known-total pricing and
  normalized source statuses with retry metadata.
- OpenAPI 3.1 document and tests for validation, special characters,
  continuation tampering/expiry, source failures and listing privacy.
- The browser itself now exercises the same v2 search route used by external
  clients.

## Compatibility and non-changes

The module-v1 API, unversioned compatibility alias, Evercade/SNES adapters and
legacy search aliases remain available. The proven marketplace extraction,
pagination, Vinted Service Binding, eBay Browse API, classification rules,
fixed-price eBay default, explicit favorites and signed deletion endpoint are
preserved.

No catalog, collection, market-value, deal-ranking or persistent server-job
model was added. Those concerns belong to clients; server-side jobs remain a
later architectural option.
