# GenericParser 0.45.2 Build 4

Build 4 is a browser/UI compatibility hotfix on top of live-proven Build 3.

## Fixed

The 0.45.0 browser controller rejected a successful HTTP 200 search response from the 0.45.2 worker solely because the exact build id differed. This produced `deployment_mismatch`, followed by `retry_exhausted`, `pages: 0` and `results: 0` even though `/api/search` had returned valid JSON.

Build 4 changes only the browser deployment handshake. Workers on the same compatible `0.45.x` release line are accepted when the API contract remains `generic-parser-module-v1`. A different release line or contract is still rejected.

## Unchanged

- search runtime: 0.45.0
- search core: 0.44.4
- operational reference: 0.44.6.5
- matching and scoring
- pagination
- seven-result packets
- retry/recovery behavior
- module contract `generic-parser-module-v1`
- Build 3 eager ASGI startup model

## Acceptance gates

- search-service files unchanged from Build 3
- browser controller regression test proves exact build equality is no longer required inside compatible 0.45.x
- health/version/diagnostics/capabilities
- CORS preflight for all public search aliases
- live module search from Evercade origin
- live legacy `/api/search` packet matching the GenericParser UI path
