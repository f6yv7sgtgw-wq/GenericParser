# GenericParser 1.3.2

Release date: 2026-08-09  
Build: `gp-132-20260809-1`  
API contract: `generic-parser-module-v1`  
Worker plan: Cloudflare Workers Paid

## Goal

1.3.2 keeps the stable 1.3.1 catalog request and its inline limit of three Vinted detail pages. Every remaining Vinted item with a canonical detail URL is queued after the catalog response and enriched through separate serial batches of three. Catalog pagination never awaits those background batches.

## Flow

1. The combined search loads Kleinanzeigen and one Vinted catalog page.
2. The Vinted component enriches at most three detail pages in parallel and returns the catalog response.
3. The browser renders and stores that response immediately.
4. Listings missing image, price or description enter a client-side queue.
5. The queue calls `/api/vinted/enrich` with up to three listings at a time.
6. The main Worker forwards only validated Vinted item URLs through the private `VINTED_BROWSER` Service Binding.
7. The Browser Run component opens the three detail pages in parallel.
8. The main Worker merges fields and re-runs price-dependent matching and traffic-light scoring.
9. The browser replaces existing cards by ID and updates its detail-progress status.

## Safety and isolation

- Batch size is fixed at 3.
- Batches are serial per browser queue.
- Each Browser Run detail navigation keeps the 6-second timeout from 1.3.1.
- Only HTTPS item URLs on `vinted.de` are accepted, and URL/item IDs must match.
- The public Browser Run hostname is not a production dependency; production uses the private Service Binding.
- A detail error is fail-open and cannot fail the catalog search.
- Starting a new search aborts the previous queue; a user stop cancels remaining batches.
- No authentication or access-control bypass is implemented.

## User-visible changes

- A compact `Vinted-Details` status card shows complete and pending counts.
- Existing result cards update in place as image, price and description arrive.
- Descriptions are visible in cards when present.
- The Eventlog records queue readiness, batch start/end, retry, failure, cancellation and completion.
- Eventlog capacity is raised to 800 current-release events.

## API changes

Additive endpoints:

- `POST /api/vinted/enrich`
- `POST /api/module/v1/vinted/enrich`

Capabilities now report both sources and the Vinted enrichment limits. `ModuleListing` explicitly retains description and detail-enrichment metadata. Full request and response documentation is in `docs/API_1.3.2.md`.

## Unchanged behavior

- Kleinanzeigen core and its 0.44.4 functional reference.
- 0.44.6.5 operational rollback reference.
- Existing search aliases and `generic-parser-module-v1` contract.
- Evercade and SNES PAL profile adapters.
- Paid-worker timing: no search cooldown, normal package pause or retry waiting.
- Anonymous public-web Vinted fallback remains fail-open only.
