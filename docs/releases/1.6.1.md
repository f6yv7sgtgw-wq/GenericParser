## Goal

Repair the browser search regression found during the direct 1.6.0 production
test, retain the complete 1.6 feature set and make the dark interface friendlier
without altering marketplace extraction or pagination.

## Root cause and controller bridge fix

The module-v2 endpoints themselves returned valid source packets. The dynamic
browser controller bridge still called `requestPage(payload)` with the old
module-v1-era function signature, while the 1.6 browser client requires
`requestPage(payload, state)`. The missing state removed `batchId` and the
continuation token before the first real browser request.

1.6.1 forwards the complete state through both controller wrappers and the
immediate-retry path. HTTP 409 and 410 continuation errors are also treated as
terminal client errors instead of being retried.

## Browser resilience and palette

- IndexedDB cleanup is fail-open, so an unavailable browser store cannot turn a
  successfully completed search into a false error.
- A dedicated runtime regression test verifies state forwarding, batch identity,
  continuation handling, storage cleanup and cache isolation.
- The interface retains dark mode but moves from near-black violet surfaces to a
  friendlier deep-blue palette with teal primary actions, warm lavender context
  accents and softer cards.
- Mobile layout, term chips, active filters, source progress, favorites and the
  compact result grid remain unchanged.

## Protected behavior

- `generic-parser-module-v1` remains unchanged and available.
- `generic-parser-module-v2` schemas and endpoint behavior are unchanged.
- Kleinanzeigen, Vinted and eBay adapters are unchanged.
- The 0.44.4 functional search core and 0.44.6.5 operational reference are
  unchanged.
- No catalog, collection, market-value, deal or persistent server-job logic is
  introduced.
